# Changelog

What changed, written for the family first. Newest at the top.
Every change adds a line under *Unreleased* in the same commit ([CONTRIBUTING](CONTRIBUTING.md)).
When a batch has been trialled, its lines move under a dated heading.

## Unreleased
- **Directions:** an arrow in the bottom bar (labelled **Maps** before the first tick) opens Google Maps with driving directions to the **next stop**, only when tapped. Village stops go to where you park (the stop set in Dispatch), otherwise the letterbox learned from GPS ticks, otherwise the street address. On Android, Google Maps keeps running in a floating window over the run. (view `address_destinations`)
- **Opening**: now plays **every time you open the app or come back to it** (after a few seconds away), not just once a day; never while you are inside a run. The chimes are **damped further**: softer, shorter, less bright (Mike, 10 Nov; [decision 0018](docs/decisions/0018-opening-every-open.md)).
- **Opening chimes lightly damped**: each note starts a touch softer, rings for a shorter time and has its bright edge taken off (Mike, 10 Nov).
- **Opening**: each stop and the pin now gets a little **twinkle**, and with Chimes switched on, **its own soft note**, rising stop by stop, in place of the run of notes at the end (Mike, 10 Nov; [decision 0017](docs/decisions/0017-opening-notes-per-stop.md)).
- **An opening animation**: the first time you open the app each day, and when you sign in, a run line draws across the screen, three stops tick green, and a pin drops and becomes the STB logo. About a second; tap to skip. **Silent unless you switch on the chimes** in **⚙ Settings → Opening** (a few soft notes; off by default because runs start at 5am). **Play the opening** in Settings shows it any time. (`js/splash.js`, [decision 0016](docs/decisions/0016-opening-animation.md))
- **Depot pick, All runs** now works from the day's **total**: all the runs' papers together, as whole bundles plus loose, using **that day's bundle size** from the sheets ("NZH 3 bundles of 80 + 79 loose = 319"). Before, it added up each run's own bundles and loose ("1 bundle + 239 loose"). If the sheets give no bundle size that day, or disagree, it says so instead of guessing (Mike, 10 Nov).
- **Second UX review** (10 Nov, [docs/ux-review.md](docs/ux-review.md#8-second-review-10-nov-2026)). On the run screen: the **bottom bar** now shows what you just ticked and the next stop in full, on their own lines above the buttons; the **street name stays at the top** while you scroll through that street; **tiles no longer grow when ticked** (who and when sit beside the ✓), so nothing moves under your thumb; the run's date is beside its name and the status stays on one line; **Unit and Suite numbers** are bolder; the "Saved: not delivered" pop-up is gone (the tile and bar already say it) and messages no longer sit on top of menus; **Other reason…** has its own box to type in; search, camera, warning and undo are line icons that look the same on every phone. Runs page: "4 of 73 done · 1 not delivered".
- **Dispatch tidy-up** from the same review: Overview in two columns (the day's work; what needs a look), the delivery score table no longer runs off its card, one link style, "✓ match" and "1 note" instead of bare numbers on Runs & sheets, a proper **+ Note** button on Complaints, and "McLaren" spelt properly.
- **To collect → Depot pick** now ends with an **All runs** line: total bundles and total loose for each paper or magazine across the day's runs (Lisa's request).
- Runs finished in the app now look like closed ones in Dispatch: **✓ Completed (app) · Lisa · Mon, 9 Nov, 6:08 am**, in the same green ("✓ Finished by Lisa" on the phones), with **Set driver…** to record who did it. Runs closed in Dispatch say *(paper)* or *(app)*.
- **Runs to do / History**: the Runs page on the phones now shows only today's and upcoming runs that aren't finished. Finished runs (every stop ticked, or closed in Dispatch) and earlier days move to the **History** tab. Replaces *Earlier days*.
- **Dispatch, Runs & sheets: Active / History.** Active keeps every unfinished run, including earlier days, until it's finished or closed; Overview lists only the day's active runs and flags earlier runs not yet closed under Needs attention. The old *History* page is now **Change log**.
- **Fix:** stop counts on the Runs page could undercount once there were weeks of runs (the phone counted from at most 1000 ticks). Now counted in the database. (view `run_progress`)
- **Close a run in Dispatch** (for runs done on the paper sheet while we're testing): *Close run…* on the Overview and Runs & sheets asks who did it, when it finished, and whether it was done on paper (ticks every stop not ticked in the app, in the driver's name) or in the app (closes it as it is). **Reopen…** unticks only the paper ticks. The family's Runs page shows **✓ Closed, done on paper by Lisa**. (`runs.driver`, `closed_at`, `closed_by`, `close_method`, `close_note`; `tap_events.method`)
- **Fix:** *couldn't deliver* and *short* (from this morning's update) showed on the phone but were sent to the server as plain ticks, because the sync only sent a fixed list of fields. Fixed, and a test now checks the app sends every tick field the database has.
- **Couldn't deliver / short** (from the STB governance baseline): tick as usual, then **⚠** in the bottom bar for the reason (gate locked, dog, no letterbox, door code, not safe, ran out, other) or how many were left. The tile turns red or amber, other phones see it, and the original tick stays in the history. (`tap_events.outcome`, `reason`, `qty_delivered`)
- **Dispatch: delivery score (DIFOTIS)** per run on the Overview (delivered, in full, on time, in spec, couldn't deliver); couldn't-deliver stops listed under Needs attention; complaints show if that day's delivery was a couldn't-deliver.
- **Policies have dates** (start, end) and **can't contradict each other**: a clashing policy is refused with the one it clashes with, at any level, instead of one quietly winning. Clashes that appear later are flagged. (`location_policies.valid_from`, `valid_to`; views `policy_clashes`, `current_policies`)
- **Sheet fingerprint and line tracing**: each run keeps the SHA-256 of the PDF it came from, and every tile keeps the page, row and printed text of each sheet line behind it. (`runs.source_hash`)
- **Run 8 banks in Dispatch**: Hulme Bank 1/2 and Monaco Bank 1/2 are service locations with their units tied to them, from the 8 Nov photos.
- Docs: [requirements](docs/requirements.md) with IDs traced to tests, a [glossary](docs/glossary.md) of the baseline's terms, [decision 0014](docs/decisions/0014-governance-baseline.md); CI now checks requirement evidence and that decision records are never rewritten. The baseline's "Run 11" is Run 8.
- **Our order / Sheet order switch** right under the run header (once a run has been re-ordered), to flip between the family's order and the sheet's original at any time. Only changes what that phone shows.
- Totals now say **items** instead of papers or copies ("115 items"), since runs mix newspapers and magazines (WD is Woman's Day). "Papers to collect" is now **Items to collect**.
- **Depot pick** on each run card and in Papers to collect (and the dispatch Overview): bundles and loose copies per paper, straight from the key report, e.g. "NZH 1 bundle of 140 + 5 loose (includes 15 for retail)". Retail copies (NZHR) are combined with NZH, as the depot bundles them together.
- **Complaints register** (dispatch): every complaint from every key report is kept once, with the delivery record (who ticked it, when, photos) and the customer's history (how many complaints, previous date). The **Overview** summarises today's complaints; the new **Complaints** page shows patterns by kind, run, who ticked it, and repeat addresses, and lets you mark each open, disputed, accepted or closed with notes. The parser now records each complaint's kind, date, paper and subscription. (`complaints`, `complaint_register`)
- **Night mode, on by default** (Zaph's call): dark colours before the first paint, with Day and Auto (night 7pm–7am) in settings. Every colour checked for contrast in both themes; tile edges are now clearly visible.
- **Run screen rebuilt**: one slim header (back, run, 🔍, ⋯), the **purple NEXT tile** for the next stop (the list follows as you tick), and a **bottom bar** with what you just ticked, **↶ Undo**, **📷** and **Next ↓** that stays until your next tick. Everything else is in one **⋯ menu** (To do only, order, tiles, text, colours, text a link, door codes, checks, and the destructive options last in red). Unit numbers read naturally ("87 · Suite 1"). Messages no longer follow you to other screens.
- **Today home**: big **Run 6** cards (Start / Continue), the update and change line per day, Papers to collect folded away, older days tucked under **Earlier days**, and **⚙ Settings** for text, colours, tiles, Get Runs, upload, password and sign out.
- **Dispatch is its own site** (`/stb-runs/dispatch/`, and where a dispatcher lands on a laptop): sidebar, **Overview** (sheets, needs attention, progress, papers, photos), **Runs & sheets**, **History**; bulk changes confirm first and offer **Undo**; a click-to-select **map** on Addresses.
- **Design guide** ([docs/design.md](docs/design.md)): tokens, colour meanings, type scale, components and a checklist, so new screens stay consistent.
- **UX review** written ([docs/ux-review.md](docs/ux-review.md)): findings for every screen, accessibility checks and a four-phase plan. Docs only.
- **Fix (dispatch):** after **Assign**, the ticked addresses stayed ticked, so the next assignment also moved the previous batch (all 66 Run 8 addresses ended up on Reception). Ticks now clear after every bulk action, and the bar warns about ticked addresses hidden by filters. Run 8's assignments were restored from the change history to each address's first assignment (Amon 11, Hulme 12, Monaco 16, Austin 4, Reception 23).
- **Dispatch dashboard** (for App + Dispatch access): the **address register** (every address from every run sheet, added automatically, with learned GPS), **locations** (groups → operating locations where the vehicle stops → service locations where the work is done, set on a map and validated), **policies** (entry point, access notes, time windows, speed limits, restrictions, by day), and **users** (add people, App only or App + Dispatch, temporary passwords, switch off). Drivers' screens are unchanged. (`addresses`, `location_groups`, `operating_locations`, `service_locations`, `location_policies`, `dispatch_history`; `members.role`, `members.active`; Edge Function `admin-users`)
- **Change password** on the Runs page.
- **Moving tiles a long way**: while holding a tile or street, drag it to the top or bottom of the screen and the list scrolls by itself (it stopped working upwards once you had scrolled down). No more dropping it at the top and picking it up again.
- Docs as code: documentation now lives in `docs/` and changes with the code; automatic checks (tests, docs links, data model, changelog, version bump, secrets) run on every change. Docs-only change for the phones.
